# 本轮修改记录：电解槽快照异步投影

## 背景

Phase A 持续压测中，电解槽 start 核心事务同步 upsert `alarm_electrolytic_cell_ectype` 时出现真实 deadlock。该表是当前点位快照，不是历史报警事实，因此允许短暂最终一致。

本轮在分支 `test/alarm-ec-snapshot-outbox` 实施异步投影。`alarm` 主表、`alarm_electrolytic_cell` 历史扩展表、route、stop event 和 MQ ack 语义保持不变。

## 核心改动

### 快照命令表

- 新增 `alarm_electrolytic_cell_snapshot_command`。
- 使用稳定 `point_hash` 作为主键，避免自增尾部热点。
- 状态流转为 `PENDING -> PROCESSING -> DONE/FAILED`。
- 命令包含 `lock_token`、`locked_at`、`available_time`、`version` 和有限重试字段。
- start 写入 `ACTIVE` 命令；stop 仅在 `alarm_id` 匹配时写入 `DELETED` 命令，旧 stop 不会删除新 start 投影。

### 独立 worker

- 新增独立 snapshot executor，不复用 MQ consumer、stop worker 或 push 线程池。
- 按 `point_hash` 稳定排序认领，默认 `2` 个线程、每批 `100` 条。
- 命令初始可见延迟默认 `2000ms`，减少同点位 start/stop 高频覆盖时的无效认领。
- claim deadlock 最多整体重试 `3` 次，退避 `50ms`。
- 空闲 worker 进入内存暂停，默认每 `1000ms` 低频探测一次。

### 并发覆盖处理

持续压测发现：worker 已认领旧版本后，同点位命令可能被更新为新版本。此时 `markDone` 的 token/version 条件更新数量会小于预期。

本轮新增 `SnapshotProjectionSupersededException`：

- 当前事务回滚，避免提交旧投影。
- 对仍由旧 token 持有的命令无惩罚释放为延迟 `PENDING`。
- 不增加 retry count，不记录为业务失败。
- 新版本命令由后续 worker 重新认领。

## 灰度开关

```yaml
alarm:
  batch:
    electrolyticSnapshotMode: SYNC
  ec-snapshot-worker:
    dispatchEnabled: false
```

推荐灰度顺序：

1. 执行新增表 DDL，保持 `SYNC`。
2. 开启 worker 空跑。
3. 切换 `DUAL_WRITE`，核对同步投影与异步投影最终一致。
4. 切换 `ASYNC`，移除 start 核心事务中的同步快照 upsert。
5. 异常时回退 `SYNC`，保留命令表，不做破坏性回滚。
