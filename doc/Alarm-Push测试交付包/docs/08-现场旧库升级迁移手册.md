# 现场旧库升级迁移手册

> 源基线：`hpis_alarm1`旧0..4分表；目标：当前时间+容量分片、可靠stop、工单和Push消息目录版本。

## 1. 核心原则

- 原始`hpis_alarm1`只读保留，先完整备份并恢复到独立演练库。
- 不在源库直接运行任何正向DDL、存储过程或`-PrecheckOnly`执行器。
- `run-alarm-legacy-0-4-id-rewrite-migration.ps1 -PrecheckOnly`会先安装迁移SQL，可能创建审计表和补字段，因此不是纯只读检查。
- 真正只读检查使用`sql/alarm-legacy-source-precheck.sql`。
- 最终迁移必须停止旧Alarm写入，新Alarm尚未开放写入。

## 2. 当前源库只读盘点（2026-08-01）

本地`hpis_alarm1`共有27张表，五张`alarm_0..4`共98,863条报警。已确认：

- 重复alarm_id：0。
- 无法编码时间：0。
- 未关闭报警：0。
- 孤立alarm_handle：10。
- 孤立alarm_electrolytic_cell：6。

16条孤立记录会阻断当前迁移预检。默认处置口径：在演练/目标库创建带批次号的审计隔离表完整复制，再从演练工作表移除；原始`hpis_alarm1`不删除。正式现场必须由业务负责人签字确认，不能静默丢弃。

## 3. 演练拓扑

推荐：

```text
hpis_alarm1（原始只读）
    └─ 全量备份/恢复 → hpis_alarm_upgrade_test（演练与正向DDL）
                            └─ 全部验收通过后生成正式步骤和耗时
```

正式发布可采用“生产库备份后原地升级”，但必须先在同规模副本完成一次；如果现场允许切库，优先复制到新库并在验收后切换Nacos连接。

## 4. 执行前门禁

1. MySQL 8.x。
2. 备份文件完成恢复演练，不只确认文件存在。
3. 记录源码版本、JAR SHA-256和全部SQL SHA-256。
4. 停止Alarm服务和`alarm_queue`消费者。
5. `push.open=false`，Push等级过滤关闭。
6. 在源库运行只读预检并保存结果。
7. 孤立记录、重复记录、非法时间和容量阻断全部有处置结论。
8. `maxRows=5000000`、单实例`workerId=0`冻结后不得在同一迁移批次修改。

## 5. Alarm SQL顺序

所有脚本以仓库`hpis-alarm/src/main/resources/sql/`为事实源：

1. `alarm-time-capacity-sharding.sql`：补分片时间字段并创建分片目录、CID路由、stop、快照命令基础表。
2. `alarm-configure-workorder-migration.sql`：配置推送字段、工单事实表、handle工单字段和索引。
3. `alarm-extension-del-flag-migration.sql`：按实际缺失情况补扩展表逻辑删除列。
4. `alarm-electrolytic-cell-ectype-point-index-migration.sql`：仅在旧点位主键结构且重复/空键预检通过时执行。
5. `alarm-legacy-0-4-id-rewrite-migration.sql`：安装迁移过程、重写旧ID、复制数据、重建路由和审计。

`alarm-stop-event-processing-claim-migration.sql`和`snapshot-command-migration.sql`只用于已存在旧版不完整表；基础分片脚本已经创建完整结构时必须跳过。旧`alarm-time-capacity-sharding-migration-template.sql`保留为历史单月模板，不再作为0..4全量升级首选。

前四个结构脚本只能在从源库恢复出的演练/目标库执行。使用MySQL login-path的参考命令：

```powershell
$mysql = '<MYSQL_HOME>/bin/mysql.exe'
$db = 'hpis_alarm_upgrade_test'

& $mysql --login-path=hpis-migration --database=$db `
  --execute="source D:/studyProject/hpis2.0/hpis/hpis-alarm/src/main/resources/sql/alarm-time-capacity-sharding.sql"
& $mysql --login-path=hpis-migration --database=$db `
  --execute="source D:/studyProject/hpis2.0/hpis/hpis-alarm/src/main/resources/sql/alarm-configure-workorder-migration.sql"
& $mysql --login-path=hpis-migration --database=$db `
  --execute="source D:/studyProject/hpis2.0/hpis/hpis-alarm/src/main/resources/sql/alarm-extension-del-flag-migration.sql"

# 只有ectype重复/空键预检通过，且目标表仍是旧alarm_id主键时才执行。
& $mysql --login-path=hpis-migration --database=$db `
  --execute="source D:/studyProject/hpis2.0/hpis/hpis-alarm/src/main/resources/sql/alarm-electrolytic-cell-ectype-point-index-migration.sql"
```

每个命令后都必须检查退出码和`information_schema`实际状态。`ectype`主键脚本不可重复执行；任何DDL中途失败都先停止，不得盲目重跑整份脚本。

## 6. 孤立记录审计隔离

隔离SQL必须由DBA根据预检结果生成，规则：

- 隔离表名包含发布批次，例如`alarm_migration_orphan_handle_20260802`。
- 使用`CREATE TABLE ... LIKE`后`INSERT ... SELECT`完整保留字段。
- 对比隔离表数量和校验值后，才允许在演练工作库移除孤立行。
- 原始源库不执行删除。
- 正式迁移报告记录旧表、旧ID、隔离原因、数量、操作人和审批人。

不在通用交付SQL中自动删除孤立数据，防止现场不同版本误删。

## 7. 迁移执行

先完成结构脚本，然后：

```powershell
powershell -ExecutionPolicy Bypass `
  -File .\hpis-alarm\src\main\resources\scripts\run-alarm-legacy-0-4-id-rewrite-migration.ps1 `
  -Database hpis_alarm_upgrade_test `
  -HostName 127.0.0.1 -Port 3306 -User root `
  -MaxRows 5000000 -WorkerId 0 -HotHours 24 -StaleExpireDays 30 `
  -OutputFile D:\migration-output\alarm-id-mapping.csv
```

密码使用MySQL login-path或交互/进程环境注入，不写入文档、脚本和Git。

只有最新`alarm_legacy_migration_run.status=PASS`、全部audit为PASS且CSV行数等于映射表行数才成功。

## 8. Push与System同步

1. 备份`hpis_push`。
2. 尚未部署企业微信对象时执行`20260716_wecom_push_incremental.sql`；该脚本整体非幂等，部分部署环境由DBA拆分缺失项。
3. 执行`20260731_push_message_dict_filter.sql`。
4. 通过System字典API维护`push_message_group`和`alarm_rank=1/2/3`。
5. 刷新并只读验证Redis`sys_dict2:*`。
6. 为现有配置messageType补目录，当前至少10/25。
7. `sql/push-dict-filter-precheck.sql`的missing结果为空，且三个`problem_count`全为0后才允许开启过滤。

禁止用生产SQL直接临时写Redis。Redis临时键只允许隔离本地联调，并在结束后删除。

## 9. 启动和灰度

1. 使用07号文档标准配置启动Push，过滤开关false。
2. 验证目录元数据、主动配置和动态队列冷启动恢复。
3. 启动Alarm，验证历史查询、新增报警和stop。
4. 验证过滤关闭时旧行为。
5. 将Push过滤开关改true并重启Push。
6. 验证等级1/2/3、无等级、类型25和站内推送。

## 10. 验收与回滚

- 使用`alarm-upgrade-postcheck.sql`保存结构和审计证据。
- 随机抽取各月份、各旧分表和电解槽数据，按CSV新ID查询。
- 验证时间范围分页、详情、确认、处理、删除和stop。
- 新应用开放写入前可以回退到原始库和旧应用。
- 新应用开放写入后再切回旧库会产生双写差异，不能把修改Nacos当作无损回滚。
- Push功能问题优先关闭等级过滤；Alarm推送问题优先`push.open=false`。
