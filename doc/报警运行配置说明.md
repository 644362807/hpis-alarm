# hpis-alarm Nacos 运行配置全量说明

> 适用代码：当前工作区 `hpis-alarm`。核对日期：2026-07-21。
> 配置证据：本机 Nacos 客户端快照 `DEFAULT_GROUP/hpis-alarm-dev.yml` 与 `DEFAULT_GROUP/application-dev.yml`，快照时间均为 2026-07-20 19:03:16。
> 注意：核对时本机 `127.0.0.1:8848` 未启动，因此“当前值”是最近一次客户端快照，不等于对 Nacos 服务端的实时查询结果。

## 1. 先看结论

1. `hpis-alarm` 的配置不是只有一个文件：本地 `bootstrap.yml` 决定服务名、环境和 Nacos 地址；共享 `application-dev.yml` 提供 Redis、RabbitMQ、Feign、文件路径等；应用专属 `hpis-alarm-dev.yml` 提供数据库、邮件和全部 `alarm.*`。
2. “Nacos 里没写”不等于“不生效”。大部分 `alarm.*` 在 Java 类中有默认值，省略后仍会运行。
3. “Nacos 当前值”也不等于“代码默认值”。例如当前快照把 `alarm.batch.insertConsumerBatchEnabled` 配为 `true`，而代码默认是 `false`。
4. 当前使用的是自定义 Java API 分片：`alarm.sharding.enabled=true`；同时 `spring.shardingsphere.enabled=false` 用于关闭旧 ShardingSphere Starter 自动配置。这两个开关含义不同，不能合并理解。
5. 当前数据源代码只读取 `url`、`username`、`password`、`driver-class-name`。快照里的 `initial-size`、`max-active`、`validation-query` 等 Druid 风格参数没有传入自定义 Hikari 数据源，属于“看起来配了，实际没生效”。
6. 当前快照中的 `alarm.profile.*` 没有任何代码读取入口，全部无效；`alarm.sharding.includeLegacyTables` 也只剩兼容字段，当前路由不再读取。
7. `thread.pool.core-pool-size`、`maximum-pool-size`、`work-queue-size` 没有代码默认值，缺失时可能因 `Integer` 为 `null` 导致线程池 Bean 初始化失败，属于启动必配。
8. `file.path` 使用无默认值的 `@Value("${file.path}")`，无论是否马上上传文件，启动环境都必须提供。
9. Nacos 发布不代表所有项都能热生效。数据源、条件 Bean、MQ listener、线程池、WebSocket、`@Scheduled` 周期等结构性配置均按“修改后重启”处理。

## 2. 三个配置文件分别做什么

| 配置源 | 当前 DataId/文件 | 用途 | 是否应放敏感信息 |
| --- | --- | --- | --- |
| 本地启动文件 | `hpis-alarm/src/main/resources/bootstrap.yml` | 端口、服务名、profile、Nacos 地址、账号、共享 DataId | 不建议把生产密码固化进 Git；生产用环境变量或部署参数覆盖 |
| Nacos 共享配置 | `application-dev.yml` | Redis、RabbitMQ、Feign/Ribbon、Actuator、`file.path`、Logback 入口 | 可以配置，但密码应使用密文/外部 Secret，不应明文进入文档 |
| Nacos 应用配置 | `hpis-alarm-dev.yml` | alarm 数据源、邮件、`alarm.*`、WebSocket、线程池、日志 | 同上 |

当前 `spring.application.name=hpis-alarm`、`spring.profiles.active=dev`、扩展名为 `yml`，所以应用专属 DataId 按 Nacos 默认规则解析为 `hpis-alarm-dev.yml`。`shared-configs` 又显式加载 `application-dev.yml`。

若同一个键在多个来源重复出现，应通过 `/actuator/env` 或启动日志确认最终值。命令行 `--key=value`、JVM 系统属性、环境变量还可能覆盖远端配置，不要只看 Nacos 页面判断最终生效值。

## 3. 本文术语

| 术语 | 含义 |
| --- | --- |
| 当前快照值 | 2026-07-20 Nacos 客户端缓存中的值；不是实时服务端查询 |
| 代码默认值 | Nacos 完全不写该键时，Java 字段、占位符或框架使用的值 |
| 有效范围/兜底 | 运行代码真正接受或钳制后的范围；不等同于“推荐范围” |
| 启动必配 | 缺失会导致占位符解析、Bean 创建或核心数据源启动失败 |
| 条件必配 | 只有打开某功能或部署形态时才必须显式配置 |
| 建议显式 | 代码有默认值，但生产为避免升级漂移，建议在 Nacos 明写 |
| 可省略 | 省略后默认值安全且含义明确 |
| 无效/历史 | 当前代码不读取，修改不会改变运行行为 |

Spring Boot relaxed binding 允许 `maxRowsPerSlice` 与 `max-rows-per-slice` 绑定到同一 Java 字段。本文表格优先保留当前快照中已经使用的写法。特别注意：部分 `@Scheduled` 占位符直接写成了 camelCase，例如 `alarm.stop-worker.dispatchIntervalMs`；要修改这些调度周期时，建议严格使用表格中的原始键名并重启，不要只依赖 relaxed binding。

## 4. 最简配置

### 4.1 能运行当前“新分片 + MQ/Redis”链路的最简合并示例

下面是“功能意义上的最简”，不是把所有生产参数都省掉。真实密码必须由 Secret 或环境变量提供。

```yaml
spring:
  autoconfigure:
    exclude: com.alibaba.druid.spring.boot.autoconfigure.DruidDataSourceAutoConfigure
  shardingsphere:
    # 关闭旧 Starter YAML 规则；自定义分片由 alarm.sharding.enabled 控制。
    enabled: false
    datasource:
      ds:
        driver-class-name: com.mysql.cj.jdbc.Driver
        url: jdbc:mysql://<mysql-host>:3306/hpis_alarm?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
        username: ${MYSQL_USER}
        password: ${MYSQL_PASSWORD}
  redis:
    host: <redis-host>
    port: 6379
    password: ${REDIS_PASSWORD:}
  rabbitmq:
    host: <rabbitmq-host>
    port: 5672
    username: ${RABBITMQ_USER}
    password: ${RABBITMQ_PASSWORD}
    virtual-host: /

file:
  # @Value 没有默认值，必须存在；目录要可写，建议以 / 结尾。
  path: <writable-temp-directory>/

thread:
  pool:
    # 三项没有代码默认值，必须填写。
    core-pool-size: 4
    maximum-pool-size: 8
    work-queue-size: 1000

alarm:
  sharding:
    enabled: true
    # 单实例可用 0；多实例不能都用 0。
    id:
      workerId: 0
```

未配置的 `alarm.stop-worker.*`、`alarm.batch.*`、`alarm.sql-log.*` 会使用代码默认值。邮件、WebSocket 和 Push 可按业务是否使用再补。

### 4.2 保守本地调试最简配置

如果只验证启动、接口和数据库，不希望 RabbitMQ 自动消费，也不希望调用外部服务，可在非生产环境增加：

```yaml
spring:
  rabbitmq:
    listener:
      simple:
        auto-startup: false
      direct:
        auto-startup: false

alarm:
  internal-test:
    remote-call-stub-enabled: true
    push-mq-stub-enabled: true
```

这两个 stub 会改变真实副作用，严禁发布到生产。

## 5. 本地 bootstrap.yml：启动与 Nacos 连接

这些键当前写在本地 `bootstrap.yml`，严格来说不是 Nacos 远端内容，但它们决定远端配置能否加载。

| 配置项 | 当前值 | 是否必须 | 默认/有效值 | 用途与使用方式 |
| --- | --- | --- | --- | --- |
| `server.port` | `8806` | 建议显式 | Spring Boot 默认 `8080`；端口 `1..65535` | alarm HTTP 服务端口；改动后重启，并同步网关/防火墙 |
| `spring.main.allow-bean-definition-overriding` | `true` | 当前架构建议保留 | Spring Boot 2.3 默认 `false` | 允许同名 Bean 覆盖；本模块自定义 `@Primary` 分片数据源，改成 `false` 需先验证 Bean 冲突 |
| `spring.application.name` | `hpis-alarm` | 必须 | 无业务默认 | 决定 Nacos 服务名、日志目录变量和应用 DataId 前缀；不要随意改名 |
| `spring.profiles.active` | `dev` | 环境必配 | 未配时使用默认 profile | 决定加载 `*-dev.yml`；生产应由部署参数覆盖为 `prod`，不能沿用 `dev` |
| `spring.cloud.nacos.discovery.server-addr` | `127.0.0.1:8848` | 使用服务发现时必须 | Nacos 客户端通常回退本机地址 | 服务注册/发现地址，格式 `host:port`，集群可逗号分隔 |
| `spring.cloud.nacos.discovery.username` | 已配置 | 开启鉴权时必须 | 空 | 服务发现登录账号；不要在文档或 Git 中写真实生产值 |
| `spring.cloud.nacos.discovery.password` | 已配置 | 开启鉴权时必须 | 空 | 服务发现密码；使用 Secret 覆盖 |
| `spring.cloud.nacos.config.server-addr` | `127.0.0.1:8848` | 使用配置中心时必须 | Nacos 客户端通常回退本机地址 | 配置中心地址；可与 discovery 不同 |
| `spring.cloud.nacos.config.file-extension` | `yml` | 建议显式 | 依赖客户端版本，当前项目固定 `yml` | 决定应用 DataId 后缀和 YAML 解析器 |
| `spring.cloud.nacos.config.username` | 已配置 | 开启鉴权时必须 | 空 | 配置中心账号 |
| `spring.cloud.nacos.config.password` | 已配置 | 开启鉴权时必须 | 空 | 配置中心密码 |
| `spring.cloud.nacos.config.context-path` | `/nacos` | 非默认部署条件必配 | 当前显式 `/nacos` | Nacos HTTP 上下文；反向代理路径变化时同步修改 |
| `spring.cloud.nacos.config.shared-configs[0]` | `application-dev.yml` | 当前共享架构必须 | 无 | 加载公共 Redis、RabbitMQ、Feign、`file.path`；当前未显式写 `group/refresh`，使用客户端默认 |

## 6. 数据源与 ShardingSphere 外层配置

### 6.1 真正被自定义数据源读取的项

`AlarmDynamicShardingConfig` 和 `AlarmShardingDataSourceFactory` 只绑定 `spring.shardingsphere.datasource.ds` 下的四个 `DataSourceProperties` 字段，再手工创建 `HikariDataSource`。

| 配置项 | 当前快照值 | 是否必须 | 默认/有效值 | 用途与风险 |
| --- | --- | --- | --- | --- |
| `spring.shardingsphere.enabled` | `false` | 新分片模式建议显式 `false` | ShardingSphere 4.1.1 Starter 默认 `true` | 只控制旧 Starter 自动配置；不控制自定义 `alarm.sharding.enabled`。当前设 `false` 是为了避免两套规则并存 |
| `spring.shardingsphere.datasource.ds.url` | 已配置，已脱敏 | 启用新分片后启动必配 | 无 | MySQL JDBC URL；库名应为 `hpis_alarm`，时区和字符集需按环境确认 |
| `spring.shardingsphere.datasource.ds.username` | 已配置，已脱敏 | 数据库鉴权时必须 | 无 | 物理库账号，需有业务 DML、分片建表和元数据维护所需权限 |
| `spring.shardingsphere.datasource.ds.password` | 已配置，已脱敏 | 数据库鉴权时必须 | 无 | 物理库密码；禁止明文复制到运行文档 |
| `spring.shardingsphere.datasource.ds.driver-class-name` | `com.mysql.cj.jdbc.Driver` | 建议显式 | 驱动可根据 URL 推断 | MySQL 驱动类；当前依赖已包含 Connector/J |

### 6.2 当前快照中存在，但自定义 Hikari 数据源不读取的项

| 配置项 | 当前值 | 当前状态 | 原本含义/现在怎么处理 |
| --- | --- | --- | --- |
| `spring.shardingsphere.datasource.names` | `master` | 自定义链路无效 | 旧 Starter 的数据源名称列表；自定义工厂固定使用名称 `ds` |
| `spring.shardingsphere.datasource.ds.type` | `com.zaxxer.hikari.HikariDataSource` | 自定义链路无效 | 旧 Starter 根据类型反射建池；当前代码直接 `new HikariDataSource()` |
| `spring.shardingsphere.datasource.ds.initial-size` | `20` | 无效 | Druid 风格初始连接数；Hikari 不识别，当前代码也未读取 |
| `spring.shardingsphere.datasource.ds.max-active` | `200` | 无效且容易误判容量 | Druid 最大连接数；当前 Hikari 仍使用自身默认最大池大小，不能把 `200` 当作实际值 |
| `spring.shardingsphere.datasource.ds.max-wait` | `25000` | 无效 | Druid 获取连接等待时间；若要配置 Hikari，需代码增加显式绑定后再使用 |
| `spring.shardingsphere.datasource.ds.min-evictable-idle-time-millis` | `1814400` | 无效 | Druid 空闲回收阈值 |
| `spring.shardingsphere.datasource.ds.min-idle` | `20` | 无效 | Druid 最小空闲数；没有传入 Hikari |
| `spring.shardingsphere.datasource.ds.test-on-borrow` | `true` | 无效 | Druid 借出校验开关 |
| `spring.shardingsphere.datasource.ds.test-on-return` | `true` | 无效 | Druid 归还校验开关 |
| `spring.shardingsphere.datasource.ds.test-while-idle` | `true` | 无效 | Druid 空闲校验开关 |
| `spring.shardingsphere.datasource.ds.validation-query` | `SELECT 1` | 无效 | Druid 校验 SQL；Hikari 默认使用 JDBC4 `isValid` |
| `spring.shardingsphere.datasource.ds.validation-query-timeout` | `2000` | 无效 | Druid 校验超时 |
| `spring.shardingsphere.datasource.ds.time-between-eviction-runs-millis` | `1814400` | 无效 | Druid 驱逐扫描周期 |
| `spring.shardingsphere.datasource.ds.time-between-connect-error-millis` | `60000` | 无效 | Druid 连接错误退避时间 |
| `spring.shardingsphere.datasource.ds.pool-prepared-statements` | `true` | 无效 | Druid PreparedStatement 缓存开关；MySQL/Hikari 应通过 JDBC URL 和驱动配置处理 |
| `spring.shardingsphere.datasource.ds.max-pool-prepared-statement-per-connection-size` | `20` | 无效 | Druid 单连接 PS 缓存上限 |

结论：当前文档不能把 `max-active: 200` 当作真实数据库连接池容量。若要调整 Hikari 连接池，必须先修改代码把 `maximum-pool-size`、`minimum-idle`、`connection-timeout` 等绑定到实际 `HikariDataSource`；仅改 Nacos 无效。

| `alarm.ec-snapshot-worker.workerThreads` | 未配置 | 可省略 | `2`；钳制 `1..16` | 独立投影线程池线程数；改后重启 |

| `alarm.ec-snapshot-worker.claimRetryBackoffMs` | 未配置 | 可省略 | `50ms`；钳制 `10..1000ms` | claim 第 N 次重试等待 `backoff * N` |
| `alarm.ec-snapshot-worker.retryDelayMs` | 未配置 | 可省略 | `5000ms`；最小 `100ms` | 投影失败释放命令后的重试延迟 |
| `alarm.ec-snapshot-worker.initialAvailableDelayMs` | 未配置 | 可省略 | `2000ms`；钳制 `0..5000ms` | start/stop 生成命令后首次可认领延迟，避免与核心事务争抢同一点位锁 |

| `alarm.ec-snapshot-worker.recoveryIntervalMs` | 未配置 | 可省略 | `10000ms` | 超时恢复扫描周期；修改需重启 |

| `alarm.ec-snapshot-worker.idleProbeIntervalMs` | 未配置 | 可省略 | `1000ms`；运行最小 `1ms` | idle 后低频兜底探针周期 |

安全切换顺序：`SYNC` → 执行命令表迁移 → `dispatchEnabled=true` 并重启 → `DUAL_WRITE` 观察命令积压与投影一致性 → 验收后 `ASYNC`。回滚时先从 `ASYNC` 回 `DUAL_WRITE` 或 `SYNC`，等待命令排空，再关闭 worker。

| 启动预建月份 | `preCreateMonths=2` | 默认/建议 `0` | 每次启动会额外创建未来两个月 `00` 表，和月末预热职责重复 |
| 旧表兼容 | `includeLegacyTables=true` | 默认 `false`，且当前代码不读取 | 产生“仍在查旧表”的错误认知 |
| MQ 批量 consumer | `insertConsumerBatchEnabled=true` | 代码默认 `false` | 当前已切到 batch listener；回滚需设 `false` 并重启 |
| actualDataNodes | 快照未配置 | 默认当前月 `255`、下月 `9` | 默认已经生效，但运维从 Nacos 页面看不出来 |
| rule refresh/月末预热 | 快照未配置 | 整组默认开启 | 任务会运行，不能因为 Nacos 无键就以为关闭 |
| stop claim 重试/初始延迟 | 快照未配置 | 使用代码默认 | 新代码行为由默认控制，建议生产明写 |
| 电解槽快照 worker | 快照未配置 | worker 默认不派发、模式默认 `SYNC` | 当前仍是同步快照语义，不能直接把模式切 `ASYNC` |
| Push 门禁 | 快照未配置 | `push.open=false`、`require-matched-config=true` | 当前默认不 Push；若别处覆盖 `push.open=true`，则必须命中配置才推送 |
| 断线去重 TTL | 快照未配置 | `1800s` | Redis 去重仍会按 30 分钟运行 |
| Hikari 最大连接数 | 快照看似 `max-active=200` | 该键无效，实际走 Hikari 默认 | 容量评估可能高估连接池 20 倍，应优先修配置绑定再调参 |

## 18. 哪些修改必须重启

| 配置类型 | 是否重启 | 原因 |
| --- | --- | --- |
| `alarm.sharding.enabled`、数据源 URL/账号、ID workerId、actualDataNodes、rule refresh 结构 | 必须 | 条件 Bean/DataSource/分片规则在启动时创建 |
| `alarm.batch.insertConsumerBatchEnabled`、batch listener 并发/批大小/prefetch | 必须 | listener Bean 和容器工厂在启动时创建 |
| stop/快照 `workerThreads`、`maxInFlightBatches` | 必须 | 专用 executor 在启动时创建 |
| 所有 `@Scheduled` cron/fixedDelay，例如 `dispatchIntervalMs`、recovery/cleanup interval | 必须 | 调度触发器初始化时解析，不应假定远端更新会重建 |
| WebSocket URL/心跳、`thread.pool.*`、邮件连接、日志文件路径/滚动 | 必须 | 对应 Bean/Appender 在启动时构造 |
| 普通布尔和批量边界，例如 `dispatchEnabled`、`inLimit`、`logEnabled` | 可能被配置重绑定，但生产仍建议重启或做实测 | Spring Cloud 可能重绑定 `@ConfigurationProperties`，但本项目未为每个 Bean建立明确的动态刷新契约 |
| logger 级别 | 可尝试动态刷新 | 以 `/actuator/loggers` 与实际日志为准；不要把“发布成功”当“已生效” |

## 19. 常用操作配方

### 19.1 暂停 stop 消费但不丢 MQ stop

设置 `alarm.stop-worker.dispatchEnabled=false`。新 stop 仍可靠写 `alarm_stop_event`，只是 PENDING 会积压。恢复前先查询积压规模，再设回 `true`；不要同时清空事件表。

### 19.2 回滚 RabbitMQ batch listener

设置 `alarm.batch.insertConsumerBatchEnabled=false` 并重启。旧 `RabbitMQAlarmListener` 会恢复，新 batch listener 会被条件关闭。切换前确认队列没有被两套实例同时以不同配置消费。

### 19.3 临时查看慢 SQL

```yaml
alarm:
  sql-log:
    enabled: true
    mode: slow
    printParam: false
    slowEnabled: true
    slowMs: 200
```

观察完成后把 `enabled` 改回 `false`。生产不要为了排障同时开启 `mode=all` 和 `printParam=true`。

### 19.4 快速验证月末预热

仅测试环境临时设置：

```yaml
alarm:
  sharding:
    rule-refresh:
      month-end-pre-create-enabled: true
      month-end-pre-create-check-last-day: false
      month-end-pre-create-cron: "0/30 * * * * ?"
      month-end-pre-create-next-month-max-slice-no: 0
```

验证日志出现 `alarm sharding next month pre-create finished` 和 `alarm sharding rule refresh success` 后，必须恢复 `check-last-day=true` 与生产 cron，并重启。

### 19.5 多实例 workerId

每个实例的 `alarm.sharding.id.workerId` 必须唯一且在 `0..255`。共享 Nacos DataId 只能给出公共默认值，推荐通过实例级环境变量或启动参数覆盖，例如 `--alarm.sharding.id.workerId=3`。扩容前先登记已占用 workerId，不能随机分配。
