## 灰度顺序

1. 先部署 DDL 和代码，保持 `electrolyticSnapshotMode=SYNC`、`dispatchEnabled=false`。
2. 开启 snapshot worker 空跑。
3. 切换 `DUAL_WRITE`，核对同步投影和命令最终投影。
4. 切换 `ASYNC`，观察 snapshot command 的 `PENDING/PROCESSING/FAILED`、route missing、deadlock 和 fallback。
5. 异常时回退 `SYNC`。命令表保留，不做破坏性回滚。

## 监控

- `alarm_electrolytic_cell_snapshot_command` 按状态数量和最长等待时间。
- snapshot claim deadlock retry、投影失败、超时回收、superseded 次数。
- `alarm_stop_event` 的 `PENDING/PROCESSING/FAILED` 和最长等待时间。
- `ROUTE_MISSING_RETRY` 次数、涉及行数和最长等待时间。
- RabbitMQ `alarm_queue.ready/unacked`。
- MySQL 锁等待、慢 SQL 和事务时长。
- 禁止在性能环境开启 MyBatis DEBUG。
