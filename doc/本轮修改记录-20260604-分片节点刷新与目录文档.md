# 本轮修改记录：分片节点刷新与目录文档

## 背景

查询 `2026-08-01 10:00:00` 到 `2026-08-10 10:00:00` 报警列表时，ShardingSphere 4.1.1 报错 `Actual table [ds].[alarm_202608_00] is not in table config`。根因是运行中新建的月度分片表不会自动进入 ShardingSphere 已创建 DataSource 的 `actualDataNodes`。

## 改动范围

- 创建分支 `codex/alarm-sharding-rule-refresh-test`。
- 将 ShardingSphere DataSource 构建改为明确 actualDataNodes。
- 新增可刷新 DataSource 代理，外部 Spring/MyBatis 持有稳定 Bean。
- 新增月度规则刷新任务，刷新失败保留旧 DataSource。
- actualDataNodes 规则改为历史实际表 + 当前月 `00..255` + 下月配置范围。
- 移除 legacy `0..4` 表参与注册和路由。
- 新增单元测试和项目目录功能说明。

## 关键文件

| 文件 | 说明 |
| --- | --- |
| `AlarmDynamicShardingConfig.java` | 暴露可刷新代理 DataSource，并抽出 DataSource 构建工厂。 |
| `AlarmShardingDataSourceFactory.java` | 根据最新表注册信息创建新的 ShardingSphere DataSource。 |
| `RefreshableAlarmShardingDataSource.java` | 原子切换内部 DataSource，旧实例延迟关闭。 |
| `AlarmMonthlySliceTableManager.java` | 生成 actualDataNodes，历史按实际表，当前月和下月按配置预注册。 |
| `AlarmTimeCapacityShardingAlgorithm.java` | 路由结果过滤到 ShardingSphere 已注册节点，避免返回未注册物理表。 |
| `AlarmShardProperties.java` | 新增 `actualDataNodes` 和 `ruleRefresh` 配置，legacy 开关标记为废弃兼容项。 |
| `AlarmShardingRuleRefreshJob.java` | 月度低峰刷新规则，失败只记录错误并保持旧实例。 |
| `项目目录功能说明.md` | 项目目录和核心类职责快速索引。 |

## 验证项

- actualDataNodes 生成包含历史实际 `yyyyMM_nn` 表。
- 当前月默认生成 `00..255`。
- 下个月默认生成 `00`，配置为 `3` 时生成 `00..03`。
- 不生成 legacy `alarm_0..4`。
- DataSource 刷新成功后代理切换到新实例。
- DataSource 刷新失败后仍使用旧实例。
