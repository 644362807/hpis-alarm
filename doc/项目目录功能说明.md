# 项目目录功能说明

## 说明

本文用于快速了解 `hpis-alarm` 模块的目录结构、核心类职责和本轮分片刷新改造入口。后续每轮涉及架构或关键链路改动时，需要同步维护本文。

## 主目录

| 路径 | 功能 |
| --- | --- |
| `src/main/java/com/hpis/alarm/config` | 模块级配置、线程池、运行参数绑定。 |
| `src/main/java/com/hpis/alarm/config/sharding` | 报警时间容量分片、ID 编码、cid 路由索引、ShardingSphere 数据源构建与刷新。 |
| `src/main/java/com/hpis/alarm/controller` | HTTP 接口入口，包含报警列表、详情、增删改查等外部访问路径。 |
| `src/main/java/com/hpis/alarm/domain` | MyBatis/MyBatis-Plus 持久化实体。 |
| `src/main/java/com/hpis/alarm/dto` | 接口和服务间传输对象。 |
| `src/main/java/com/hpis/alarm/mapper` | Mapper 接口，对应 `src/main/resources/mapper/alarm` XML。 |
| `src/main/java/com/hpis/alarm/service` | 业务服务接口、可靠消警、批量插入、stop event、side effect 等核心服务。 |
| `src/main/java/com/hpis/alarm/service/impl` | 业务服务实现，`AlarmServiceImpl` 是报警主链路实现。 |
| `src/main/java/com/hpis/alarm/task` | 定时任务和后台 worker，包括 cid 生命周期、stop worker、分片规则刷新任务。 |
| `src/main/java/com/hpis/alarm/transfer` | MQ 消费入口，包含单条 listener 和 consumer batch listener。 |
| `src/main/resources/mapper/alarm` | MyBatis XML SQL。 |
| `src/main/resources/sql` | 分片、stop event、快照等迁移脚本。 |
| `src/test/java/com/hpis/alarm` | 单元测试、XML 合同测试、链路局部测试和压测辅助入口。 |
| `doc` | 中文设计说明、运行配置、压测报告、本轮修改记录。 |

## 分片相关类

| 类 | 职责 |
| --- | --- |
| `AlarmDynamicShardingConfig` | 在 `alarm.sharding.enabled=true` 时创建物理 DataSource、分片管理器、分片算法、可刷新代理 DataSource。 |
| `AlarmShardingDataSourceFactory` | 根据当前 actualDataNodes 重新构建 ShardingSphere 4.1.1 DataSource。 |
| `RefreshableAlarmShardingDataSource` | Spring/MyBatis 持有的稳定 DataSource 代理，刷新时原子切换内部 ShardingSphere DataSource。 |
| `AlarmShardingRuleRefreshService` | 统一处理月度刷新和建表后主动刷新，包含单飞、去抖、afterCommit、失败保留旧实例。 |
| `AlarmMonthlySliceTableManager` | 管理月度容量分片元数据、动态建表、实际历史表扫描、当前月和下月节点预注册。 |
| `AlarmTimeCapacityShardingAlgorithm` | ShardingSphere 复杂分片算法，按上下文 suffix、alarm_id、cid、时间范围、设备或网关路由。 |
| `AlarmShardProperties` | `alarm.sharding.*` 配置绑定，包含 actualDataNodes 和 rule-refresh 配置。 |
| `AlarmShardingRuleRefreshJob` | 月度低峰刷新任务，重建 DataSource 成功后切换，失败保留旧 DataSource。 |
| `AlarmShardingNextMonthPreCreateJob` | 月末预热任务，创建下个月 `00` 物理表并显式刷新 DataSource。 |

## 本轮关注边界

- 旧 `alarm_0..4`、`alarm_handle_0..4`、`alarm_electrolytic_cell_0..4` 已清理，本轮不再注册、不再兜底查询。
- ShardingSphere 4.1.1 不会在运行中新建表后自动感知 actualDataNodes，需要通过重建 DataSource 并代理切换刷新规则。
- 历史月份按数据库实际存在的 `yyyyMM_nn` 表注册；当前月预注册 `00..255`；下个月默认预注册 `00..09`。
- 当前按单实例运行设计，月末预热不引入分布式锁；多实例部署前需要补充跨实例建表互斥。
- 新增测试入口覆盖 actualDataNodes 生成、代理刷新成功、刷新失败保留旧实例。
