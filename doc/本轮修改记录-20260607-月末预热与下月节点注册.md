# 本轮修改记录-20260607-月末预热与下月节点注册

## 背景

ShardingSphere 4.1.1 的 actualDataNodes 在 DataSource 创建时固定。上一轮已经支持可刷新 DataSource、当前月预注册和建表后主动刷新。本轮将下个月预热从“启动顺带创建”调整为“月末专门预热”，避免服务长期运行时跨月前缺少明确准备动作。

## 目标

- 启动默认只创建当前月 `00` 三张业务物理表。
- 当前月 actualDataNodes 默认注册 `00..255`。
- 下个月 actualDataNodes 默认注册 `00..09`。
- 月末任务默认创建下个月 `00` 三张业务物理表。
- 月末任务完成后显式刷新一次 DataSource。

## 非目标

- 不恢复 legacy `alarm_0..4` 支持。
- 不改变报警增删改查业务语义。
- 不新增 MQ 暂停/恢复控制。
- 当前按单实例运行设计，不引入分布式锁。

## 关键实现

- `AlarmShardProperties`：
  - `preCreateMonths` 默认改为 `0`。
  - `actualDataNodes.nextMonthMaxSliceNo` 默认改为 `9`。
  - `ruleRefresh` 新增月末预热配置。
- `AlarmMonthlySliceTableManager`：
  - 保留普通动态建表后的主动刷新。
  - 新增下个月预建入口，月末预热调用时不触发建表后防抖刷新。
- `AlarmShardingNextMonthPreCreateJob`：
  - 默认每天 `23:50` 触发。
  - 默认只在本月最后一天执行。
  - 创建下个月 `00` 后调用 `refreshNow("month-end-precreate")`。

## 测试结果

本轮应至少执行：

```powershell
mvn -pl hpis-alarm -am "-Dtest=AlarmIdCodecTest,AlarmCidIndexServiceTest,AlarmTimeCapacityShardingApiTest,AlarmMonthlySliceTableManagerActualDataNodesTest,RefreshableAlarmShardingDataSourceTest,AlarmShardingRuleRefreshJobTest,AlarmShardingRuleRefreshServiceTest,AlarmShardingNextMonthPreCreateJobTest" -DfailIfNoTests=false "-Dfile.encoding=UTF-8" test
```

验证重点：

- 默认启动预建月数为 `0`。
- 默认下个月节点包含 `00..09`。
- 非月末不预建、不刷新。
- 月末预建成功后刷新一次。
- 预建失败时不刷新，旧 DataSource 继续保留。
