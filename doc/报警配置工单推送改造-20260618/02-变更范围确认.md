# 变更范围确认

本文件只确认后续代码改动边界，不包含代码实现。

## hpis-alarm 预计改动范围

### 报警配置

涉及：

- `alarm_configure`
- `alarm_configure_time`
- `alarm_device_configure`
- 报警配置 Domain、Mapper、Service、Controller 入参出参。

预计改动：

- 按设计文档新增 `alarm_configure` 字段：
  - `is_device_sync`
  - `config_device_type`
  - `device_rule_json`
  - `workorder_config_id`
  - `push_message_type`
  - `config_version`
  - `sync_status`
  - `last_sync_time`
  - `last_sync_result`
- `alarm_configure_time` 可补 `alarm_configure_time_id`，便于编辑单个时间段。
- `alarm_device_configure` 保留现有设备 SN 绑定，后续按需轻量增强。

### 报警产生

涉及：

- 报警 MQ 单条和批量消费入口。
- `AlarmServiceImpl` 中报警组装、持久化、after-commit 推送。
- `AlarmMapper.xml` 单条和批量插入 SQL。
- 分片建表逻辑。

预计改动：

- 新增配置解析组件，避免在主流程中堆叠匹配逻辑。
- 报警入库前或持久化上下文中解析配置命中结果。
- 按设计文档新增 `alarm` 字段：
  - `alarm_configure_id`
  - `config_version`
  - `device_type`
  - `alarm_title`
  - `alarm_content`
  - `workorder_id`
  - `rule_snapshot_json`
  - `raw_payload_json`
- after-commit 推送 payload 增加 `pushMessageType`、`alarmConfigureId`、`configVersion`。

### 报警处理

涉及：

- `alarm_handle`
- `AlarmHandle` Domain。
- `AlarmHandleMapper.xml`。

预计改动：

- 按设计文档新增 `alarm_handle` 字段：
  - `handle_type`
  - `source_type`
  - `source_id`
  - `status_before`
  - `status_after`
  - `handle_result`
  - `attachments_json`
- 工单转派、工单同步、工单关闭使用增强后的 `alarm_handle` 记录。

### 报警工单

涉及：

- 新增 `alarm_workorder_config`。
- 新增 `alarm_workorder`。
- 新增工单 Domain、Mapper、Service、Controller。

预计改动：

- `alarm_workorder_config` 按设计文档保存自动生成、派单、超时、自动关闭报警等规则。
- `alarm_workorder` 按设计文档保存工单实例和报警快照。
- `alarm_workorder.alarm_id` 必须唯一，防止重复工单。

## hpis-push 预计改动范围

### 推送配置

涉及：

- `active_push_config`
- `pushConfigId_deviceSn`
- 推送配置 Domain、Mapper、Service。

预计改动：

- 按设计文档调整 `active_push_config.message_type` 为 `varchar(30)`。
- 按设计文档调整 `active_push_config.push_channel_type` 为 `varchar(20)`。
- 可选新增 `bind_ip`，仅在 `push_address` 无法表达绑定 IP 时使用。
- `pushConfigId_deviceSn` 本轮不强制扩表，继续保存设备 SN 与推送配置 ID 的绑定关系。

### Redis 路由

涉及：

- 推送配置写缓存。
- 推送配置删除缓存。
- 报警推送时的配置 ID 解析。

预计改动：

- 保留旧 `deviceSn#messageType` 路由兼容。
- 增加行业级和行业全部报警路由 key 语义。
- 推送投递时合并设备级、行业级、全局级配置 ID，并去重。
- 修复无命中配置时空指针风险。

## 数据库范围

需要新增或调整：

- `alarm_configure`
- `alarm_configure_time`
- `alarm_device_configure`
- `alarm`
- `alarm_handle`
- `alarm_workorder_config`
- `alarm_workorder`
- `active_push_config`

需要同步：

- 基础表 DDL。
- 分片物理表建表逻辑。
- 历史迁移模板。
- Mapper 单条和批量插入字段。

## Redis 范围

预计新增或兼容：

- 设备级：`deviceSn#pushMessageType`
- 行业级：`SCENE:{sceneType}#pushMessageType`
- 行业全部报警：`SCENE:{sceneType}#*`
- 旧路由：`deviceSn#messageType`

实际 key 名后续实现时应集中定义常量，避免散落字符串。

## MQ payload 范围

保留：

- 原有 `data`
- 原有 `tenantId`
- 原有 `deviceSn`
- 原有报警类型展示字段

新增：

- `pushMessageType`
- `alarmConfigureId`
- `configVersion`

兼容要求：

- 老消费者忽略新增字段不受影响。
- 无新增字段时推送服务回退旧 `messageType` 逻辑。

## 明确不改范围

- 不修改 RabbitMQ 队列名。
- 不修改 RabbitMQ ack/nack 语义。
- 不修改 stop 可靠关闭主链路。
- 不迁移现有 WebSocket、HTTP、MQTT 推送消费者协议。
- 不新增完整策略引擎。
- 不拆分各设备类型专属报警配置表。
- 不新增一条报警多工单实例能力。
