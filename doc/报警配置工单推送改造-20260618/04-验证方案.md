# 验证方案

本文件只记录验证方案，不包含代码实现。

## 验证目标

- 确认报警配置可按设备、行业、报警类型正确命中。
- 确认 `push_message_type` 可正确进入报警事实和推送 payload。
- 确认推送服务可按设备级、行业级、行业全部报警合并路由并去重。
- 确认同一报警最多生成一个工单实例。
- 确认旧报警入库、旧推送、stop 闭环不被破坏。

## 单元测试

### 配置解析

用例：

- 设备+报警类型配置命中。
- 行业+报警类型配置命中。
- 行业+全部报警配置命中。
- 多级配置同时存在时按优先级选择报警配置。
- 配置关闭、逻辑删除、非生效时间段时不命中。
- `push_message_type` 为空时回退 `alarm_type`。

断言：

- 返回的 `alarmConfigureId` 正确。
- 返回的 `configVersion` 正确。
- 返回的 `pushMessageType` 正确。
- 未命中配置时不抛异常。

### 推送路由

用例：

- 只命中设备级路由。
- 只命中行业级路由。
- 只命中行业全部报警路由。
- 三类路由同时命中。
- 多个路由包含重复 `active_push_config_id`。
- Redis 有租户 map 但没有目标 key。

断言：

- 返回配置 ID 去重。
- 无命中返回空列表。
- 无空指针异常。
- 日志包含 `tenantId`、`sceneType`、`deviceSn`、`pushMessageType`。

### 工单幂等

用例：

- 自动生成工单成功。
- 同一报警重复生成工单。
- 并发生成同一报警工单。
- 工单转派写处理流水。

断言：

- 同一 `alarm_id` 只有一个 `alarm_workorder`。
- 转派后工单实例数不变。
- `alarm_handle` 有工单来源记录。

## Redis 人工验证

准备数据：

- 租户 `tenantId=123`。
- 行业 `sceneType=2`。
- 设备 `deviceSn=DEV001`。
- 推送细分 `pushMessageType=GAS_LEAK`。

验证 key：

- `DEV001#GAS_LEAK` 可命中设备级配置。
- `SCENE:2#GAS_LEAK` 可命中行业级配置。
- `SCENE:2#*` 可命中行业全部报警配置。

验证步骤：

1. 保存设备级推送配置，检查 Redis key。
2. 保存行业级推送配置，检查 Redis key。
3. 保存行业全部报警配置，检查 Redis key。
4. 禁用配置，确认 Redis key 移除对应配置 ID。
5. 删除配置，确认 Redis key 移除对应配置 ID。
6. 同时命中三类 key，确认配置 ID 去重。

## 接口与 MQ 联调

### 报警配置接口

验证：

- 新增配置。
- 修改配置。
- 启用/禁用配置。
- 配置时间段。
- 配置设备绑定。
- 配置行业级规则。
- 配置行业全部报警规则。

### 报警 MQ

验证：

- 单条报警消息。
- 批量报警消息。
- 配置命中后写入报警事实。
- after-commit 后再发推送，DB 回滚时不发推送。
- 推送失败不回滚报警入库。

### 推送 MQ

验证：

- `push.alarm` 老消息仍可消费。
- 新消息携带 `pushMessageType` 时走增强路由。
- 缺失 `pushMessageType` 时回退旧 `messageType`。

## 灰度观察指标

报警服务：

- 配置命中数。
- 配置未命中数。
- 自动工单生成数。
- 工单唯一键冲突数。
- after-commit 推送投递成功数。
- after-commit 推送投递失败数。

推送服务：

- 路由命中数。
- 路由未命中数。
- 命中的配置 ID 数。
- 去重前后配置 ID 数。
- 配置队列投递成功数。
- 配置队列投递失败数。

数据库：

- 新增字段写入失败数。
- 分片表缺字段错误。
- 工单唯一键冲突。
- 慢 SQL 和锁等待。

Redis：

- 配置缓存刷新失败。
- 路由 key 缺失。
- 缓存重建耗时。
