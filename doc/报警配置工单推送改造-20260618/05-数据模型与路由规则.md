# 数据模型与路由规则

本文件只记录数据模型和路由规则设计，不包含代码实现。

字段和表结构以《报警配置最小改动方案设计文档》为主。

## 报警配置字段口径

`alarm_configure` 建议新增字段：

| 字段 | 说明 |
| --- | --- |
| `is_device_sync` | 是否需要同步下发到设备。 |
| `config_device_type` | 配置适用设备类型。 |
| `device_rule_json` | 设备差异化报警规则 JSON。 |
| `workorder_config_id` | 关联工单配置 ID。 |
| `push_message_type` | 推送消息类型，也作为本次推送细分字段。 |
| `config_version` | 配置版本号。 |
| `sync_status` | 同步状态。 |
| `last_sync_time` | 最近同步时间。 |
| `last_sync_result` | 最近同步结果或失败原因。 |

口径说明：

- 不新增额外推送细分字段。
- `push_message_type` 是推送细分的唯一字段口径。
- `push_message_type` 优先用于推送配置匹配。
- `push_message_type` 为空时回退 `alarm_configure.alarm_type`。
- `alarm_configure.alarm_type` 为空或 `*` 表示行业全部报警。

## 报警事实字段口径

`alarm` 建议新增字段：

| 字段 | 说明 |
| --- | --- |
| `alarm_configure_id` | 命中的报警配置 ID。 |
| `config_version` | 命中的配置版本。 |
| `device_type` | 设备类型。 |
| `alarm_title` | 报警标题。 |
| `alarm_content` | 报警内容。 |
| `workorder_id` | 关联报警工单 ID。 |
| `rule_snapshot_json` | 报警产生时的规则快照。 |
| `raw_payload_json` | 设备原始报警数据。 |

用途：

- 支撑历史报警追溯。
- 支撑工单和报警之间的一对一关联。
- 支撑配置变更后的历史解释。

## 报警处理字段口径

`alarm_handle` 建议新增字段：

| 字段 | 说明 |
| --- | --- |
| `handle_type` | 处理类型：确认、处理、关闭、误报、转工单、工单同步等。 |
| `source_type` | 来源：报警直接处理或工单同步。 |
| `source_id` | 来源 ID，如工单 ID。 |
| `status_before` | 处理前报警状态。 |
| `status_after` | 处理后报警状态。 |
| `handle_result` | 处理结果摘要。 |
| `attachments_json` | 附件 JSON。 |

用途：

- 复用现有报警处理流水。
- 记录工单转派、工单同步和工单关闭。
- 避免本期新增独立工单处理流水表。

## 推送配置字段口径

`active_push_config` 建议调整字段：

| 字段 | 说明 |
| --- | --- |
| `message_type` | 推送消息类型，对应 `alarm_configure.push_message_type`。 |
| `push_channel_type` | 推送渠道类型。 |
| `bind_ip` | 可选字段，仅当 `push_address` 无法表达绑定 IP 时新增。 |

`pushConfigId_deviceSn`：

- 继续保存设备 SN 与推送配置 ID 的绑定关系。
- 本期不强制新增行业字段。
- 行业级路由优先通过 Redis key 语义实现。

## 报警配置匹配规则

输入：

- `tenantId`
- `sceneType`
- `deviceSn`
- `alarmType`
- 当前时间

匹配前置条件：

- `del_flag = 0`
- `device_alarm_control = 1`
- `tenant_id` 匹配
- 生效时间段命中

匹配顺序：

1. 设备+报警类型。
2. 行业+报警类型。
3. 行业+全部报警。

行业+全部报警表达：

- `alarm_configure.alarm_type` 为空。
- 或 `alarm_configure.alarm_type = '*'`。

输出：

- `alarm_configure_id`
- `config_version`
- `push_message_type`
- `workorder_config_id`
- `rule_snapshot_json`

未命中处理：

- 不阻断报警入库。
- 记录配置未命中日志。
- 推送侧回退旧 `messageType` 逻辑。

## 推送路由规则

输入：

- `tenantId`
- `sceneType`
- `deviceSn`
- `pushMessageType`

路由 key 语义：

| 路由级别 | key 语义 | 说明 |
| --- | --- | --- |
| 设备级 | `deviceSn#pushMessageType` | 指定设备指定推送细分。 |
| 行业级 | `SCENE:{sceneType}#pushMessageType` | 指定行业指定推送细分。 |
| 行业全部报警 | `SCENE:{sceneType}#*` | 指定行业全部报警。 |
| 旧兼容 | `deviceSn#messageType` | 兼容当前推送路由。 |

合并规则：

- 同时查询设备级、行业级、行业全部报警路由。
- 采用 `UNION`。
- 按 `active_push_config_id` 去重。
- 去重后再解析配置队列并投递。

无命中处理：

- 返回空列表。
- 记录 `PUSH_ROUTE_MISS`。
- 不抛异常。
- 不影响 MQ 消费线程。

## 工单模型规则

`alarm_workorder_config`：

- 保存工单生成规则。
- `create_mode=1` 表示报警产生后自动生成工单。
- `create_mode=2/3` 后续迭代。

`alarm_workorder`：

- 一条报警最多一个工单实例。
- `alarm_id` 必须唯一。
- 保存报警、设备、派单人、优先级、状态等快照。

工单转派：

- 不新增第二张 `alarm_workorder`。
- 通过 `alarm_handle` 记录转派或工单同步流水。

工单关闭：

- 按 `alarm_workorder_config.auto_close_alarm` 决定是否自动关闭报警。
- 处理结果写入 `alarm_handle`。
