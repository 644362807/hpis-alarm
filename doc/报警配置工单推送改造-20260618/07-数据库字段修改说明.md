# 数据库字段修改说明

本文件只记录数据库字段修改设计和字段功能说明，不包含 SQL 执行和代码实现。

字段口径以《报警配置最小改动方案设计文档》为主。后续真正落库时，需要结合当前数据库版本生成正式迁移脚本，并在测试库验证后再进入联调或灰度。

## 1. alarm_configure 报警配置主表

表定位：继续作为报警配置主表，保存报警配置公共信息、设备同步信息、推送细分和工单配置入口。

| 字段 | 类型建议 | 默认值 | 是否必填 | 字段功能 |
| --- | --- | --- | --- | --- |
| `is_device_sync` | `char(1)` | `'0'` | 否 | 标记该报警配置是否需要同步下发到设备或边缘端。`0` 表示仅平台侧使用，`1` 表示配置变更后需要触发设备同步流程。 |
| `config_device_type` | `varchar(30)` | `NULL` | 否 | 标记该配置适用的设备类型，如 `INFRARED`、`PD`、`ROBOT`、`GAS`、`GATEWAY`、`COMMON`。用于配置筛选、设备差异化规则解析和后续设备同步。 |
| `device_rule_json` | `json` | `NULL` | 否 | 保存设备差异化报警规则 JSON。本期不拆分各设备类型明细配置表，设备阈值、持续时间、通道/区域/点位扩展参数可先放入该字段。 |
| `workorder_config_id` | `bigint` | `NULL` | 否 | 关联 `alarm_workorder_config.workorder_config_id`。为空表示该报警配置不自动生成工单。 |
| `push_message_type` | `varchar(30)` | `NULL` | 否 | 推送消息类型，也是本次改造的推送细分字段。报警命中配置后，优先使用该字段匹配推送配置；为空时回退 `alarm_type`。 |
| `config_version` | `int` | `1` | 否 | 配置版本号。每次影响报警产生、推送或工单行为的配置变更时递增，用于报警事实表保存历史命中版本。 |
| `sync_status` | `char(2)` | `'0'` | 否 | 设备同步状态。建议 `0` 未同步，`1` 已同步，`2` 同步失败。仅 `is_device_sync=1` 时有业务意义。 |
| `last_sync_time` | `datetime` | `NULL` | 否 | 最近一次设备同步时间。用于排查配置是否已成功下发。 |
| `last_sync_result` | `varchar(500)` | `NULL` | 否 | 最近一次设备同步结果或失败原因。用于设备同步失败后的问题定位。 |

### 写入时机

- 新增报警配置时写入默认版本和默认同步状态。
- 修改配置时，如变更报警类型、推送细分、设备规则、设备范围、工单配置或生效时间，应递增 `config_version`。
- 设备同步执行完成后更新 `sync_status`、`last_sync_time`、`last_sync_result`。

### 读取用途

- 报警产生时用于命中配置和生成规则快照。
- 推送时用于计算 `pushMessageType`。
- 工单生成时用于查找 `workorder_config_id`。
- 配置管理页面用于展示同步状态和最近失败原因。

### 注意事项

- `push_message_type` 不要和推送服务旧代码里的队列类型概念混淆；本次业务上作为推送细分使用。
- `device_rule_json` 不应承载无法被版本追溯的临时运行状态。
- `config_version` 应在服务层统一维护，避免前端直接传入任意版本。

## 2. alarm_configure_time 报警配置时间段表

表定位：继续保存报警配置自定义生效时间段。

| 字段 | 类型建议 | 默认值 | 是否必填 | 字段功能 |
| --- | --- | --- | --- | --- |
| `alarm_configure_time_id` | `bigint` | 自增 | 是 | 时间段主键。用于编辑或删除单个时间段，避免只能按 `alarm_configure_id` 全量删除重建。 |

### 写入时机

- 新增自定义时间段时自动生成。
- 修改配置时间段时，可按主键更新、删除或重建。

### 读取用途

- 当 `alarm_configure.alarm_configure_period=1` 时，报警配置解析需要读取该表判断当前时间是否命中。

### 注意事项

- 跨天时间段需要按 `start > end` 的规则处理，如 `22:00:00` 到 `06:00:00` 表示当前时间大于开始时间或小于结束时间。
- 如果当前系统继续采用全量删除重建时间段，也建议保留该主键，为后续精细编辑预留能力。

## 3. alarm_device_configure 报警配置设备关联表

表定位：保存报警配置与设备、分组、通道、区域、点位的关联关系。当前最小实现仍可只使用 `device_sn + alarm_configure_id`。

| 字段 | 类型建议 | 默认值 | 是否必填 | 字段功能 |
| --- | --- | --- | --- | --- |
| `id` | `bigint` | 自增或雪花 ID | 否 | 关联表主键。便于单条关联编辑、删除和审计。 |
| `device_sn` | `varchar(100)` | `NULL` | 否 | 设备 SN。报警上报时优先通过该字段判断设备级配置是否命中。 |
| `target_type` | `varchar(20)` | `'DEVICE'` | 否 | 关联对象类型。建议支持 `DEVICE`、`GROUP`、`CHANNEL`、`AREA`、`POINT`。本期可先默认设备级。 |
| `target_id` | `bigint` | `NULL` | 否 | 关联对象 ID。用于设备组、通道、区域、点位等扩展场景。 |
| `channel_no` | `varchar(50)` | `NULL` | 否 | 通道号。局放等多通道设备可使用。 |
| `area_sn` | `varchar(100)` | `NULL` | 否 | 区域编码。红外区域、地图区域等场景可使用。 |
| `point_id` | `bigint` | `NULL` | 否 | 点位 ID。机器狗巡检点、电解槽点位等场景可使用。 |
| `tenant_id` | `bigint` | `NULL` | 否 | 租户 ID。用于多租户隔离和后续查询优化。 |
| `del_flag` | `char(2)` | `'0'` | 否 | 逻辑删除标识。建议 `0` 存在，`2` 删除。 |

### 写入时机

- 报警配置绑定设备、分组、通道、区域、点位时写入。
- 配置修改绑定范围时更新或重建关联关系。

### 读取用途

- 报警配置解析时判断设备级配置命中。
- 行业级配置可通过无设备绑定或特定 `target_type` 表达，具体实现需保持统一规则。

### 注意事项

- 本期如只实现设备级绑定，不需要一次性使用所有扩展字段。
- 大批量设备绑定必须分批写入，避免超长 SQL。

## 4. alarm 报警事实主表

表定位：保存报警事实。新增字段用于记录配置来源、配置版本、推送细分、工单关联和报警发生时的规则快照。

| 字段 | 类型建议 | 默认值 | 是否必填 | 字段功能 |
| --- | --- | --- | --- | --- |
| `alarm_configure_id` | `bigint` | `NULL` | 否 | 报警产生时命中的报警配置 ID。未命中配置时为空，保留旧报警入库行为。 |
| `config_version` | `int` | `NULL` | 否 | 报警产生时命中的配置版本。用于解释历史报警按哪个版本规则产生、推送和生成工单。 |
| `device_type` | `varchar(30)` | `NULL` | 否 | 报警设备类型快照。用于查询、统计和后续设备差异化处理。 |
| `alarm_title` | `varchar(100)` | `NULL` | 否 | 报警标题。可由配置模板、报警类型、设备名称生成，用于列表、推送和工单标题。 |
| `alarm_content` | `varchar(500)` | `NULL` | 否 | 报警内容摘要。用于推送正文、工单描述和告警详情快速展示。 |
| `workorder_id` | `bigint` | `NULL` | 否 | 关联报警工单 ID。为空表示未生成工单。 |
| `rule_snapshot_json` | `json` | `NULL` | 否 | 报警产生时命中配置的规则快照。配置后续变更不影响历史报警追溯。 |
| `raw_payload_json` | `json` | `NULL` | 否 | 设备或边缘端上报的原始报警 JSON。用于问题排查和后续兼容新字段。 |

### 写入时机

- 报警入库时写入配置命中结果。
- 自动生成工单成功后回写 `workorder_id`。
- 未命中配置时新增字段可为空，不阻断报警主链路。

### 读取用途

- 报警详情展示配置来源和规则快照。
- 工单查询通过 `workorder_id` 关联。
- 推送失败排查可结合 `raw_payload_json` 和配置快照定位问题。

### 注意事项

- 当前 `alarm` 存在时间容量分片链路，新增字段必须同步所有分片物理表、分片建表逻辑、批量插入 SQL 和迁移模板。
- JSON 字段如数据库版本不支持原生 `json`，可用 `text` 或 `longtext` 作为兼容实现，但字段语义不变。

## 5. alarm_handle 报警处理流水表

表定位：继续作为统一报警处理流水，承载报警直接处理、确认、关闭、误报、转工单、工单同步等记录。

| 字段 | 类型建议 | 默认值 | 是否必填 | 字段功能 |
| --- | --- | --- | --- | --- |
| `handle_type` | `char(2)` | `'1'` | 否 | 处理类型。建议 `0` 确认，`1` 处理，`2` 关闭，`3` 误报，`4` 转工单，`5` 工单同步。 |
| `source_type` | `char(2)` | `'0'` | 否 | 处理来源。建议 `0` 报警直接处理，`1` 工单同步。 |
| `source_id` | `bigint` | `NULL` | 否 | 来源 ID。如工单同步时保存 `workorder_id`。 |
| `status_before` | `char(2)` | `NULL` | 否 | 处理前报警状态。用于审计和状态流转排查。 |
| `status_after` | `char(2)` | `NULL` | 否 | 处理后报警状态。用于审计和闭环验证。 |
| `handle_result` | `varchar(500)` | `NULL` | 否 | 处理结果摘要。用于直接处理说明、工单处理结果、转派原因等。 |
| `attachments_json` | `json` | `NULL` | 否 | 附件 JSON。用于保存处理图片、视频、文件地址等。 |

### 写入时机

- 报警确认、处理、关闭、误报时写入。
- 自动转工单或手动转工单时写入 `handle_type=4`。
- 工单状态变化同步报警时写入 `handle_type=5`、`source_type=1`、`source_id=workorder_id`。

### 读取用途

- 报警详情展示处理时间线。
- 工单详情展示报警侧同步记录。
- 审计报警是否完成确认、处理、关闭。

### 注意事项

- 当前 `alarm_handle` 也参与分片链路，新增字段必须同步分片建表和 Mapper。
- 工单转派不新增第二张工单，应通过处理流水表达转派行为。

## 6. alarm_workorder_config 报警工单配置表

表定位：保存报警触发后是否生成工单、如何派单、是否自动关闭报警等规则。

| 字段 | 类型建议 | 默认值 | 是否必填 | 字段功能 |
| --- | --- | --- | --- | --- |
| `workorder_config_id` | `bigint` | 雪花 ID 或自增 | 是 | 工单配置主键。被 `alarm_configure.workorder_config_id` 引用。 |
| `config_name` | `varchar(100)` | 无 | 是 | 工单配置名称。用于配置列表展示和审计。 |
| `enabled` | `char(1)` | `'1'` | 否 | 是否启用。`0` 否，`1` 是。禁用后即使报警配置关联该配置，也不自动生成工单。 |
| `create_mode` | `char(2)` | `'1'` | 否 | 工单生成方式。建议 `0` 不生成，`1` 自动生成，`2` 手动生成，`3` 确认后生成。本期优先实现 `1`。 |
| `workorder_type` | `varchar(50)` | `NULL` | 否 | 工单类型快照，如维修、巡检、隐患处理等。 |
| `workorder_priority` | `char(2)` | `NULL` | 否 | 工单优先级。可由报警等级映射或人工配置。 |
| `assignee_type` | `varchar(30)` | `NULL` | 否 | 派单类型。建议 `USER`、`ROLE`、`DEVICE_OWNER`、`AREA_OWNER`。 |
| `assignee_id` | `bigint` | `NULL` | 否 | 派单对象 ID。 |
| `assignee_name` | `varchar(100)` | `NULL` | 否 | 派单对象名称快照。避免人员名称变更影响历史工单展示。 |
| `timeout_minutes` | `int` | `0` | 否 | 工单超时时间，单位分钟。`0` 表示不启用超时。 |
| `auto_close_alarm` | `char(1)` | `'1'` | 否 | 工单关闭后是否自动关闭报警。`0` 否，`1` 是。 |
| `allow_direct_close` | `char(1)` | `'0'` | 否 | 有工单时是否允许直接关闭报警。`0` 不允许，`1` 允许。 |
| `title_template` | `varchar(200)` | `NULL` | 否 | 工单标题模板。可引用报警标题、设备名称、报警类型等变量。 |
| `content_template` | `varchar(1000)` | `NULL` | 否 | 工单内容模板。可引用报警内容、设备信息、位置、时间等变量。 |
| `tenant_id` | `bigint` | `NULL` | 否 | 租户 ID。用于多租户隔离。 |
| `del_flag` | `char(2)` | `'0'` | 否 | 逻辑删除标识。建议 `0` 存在，`2` 删除。 |

### 写入时机

- 创建或修改报警工单配置时写入。
- 报警配置关联工单配置时只保存 `workorder_config_id`，不复制配置字段。

### 读取用途

- 报警产生后判断是否自动生成工单。
- 工单生成时复制类型、优先级、派单对象、模板等信息到 `alarm_workorder`。
- 工单关闭时判断是否自动关闭报警。

### 注意事项

- 第一阶段建议只实现 `create_mode=1` 自动生成，降低改动范围。
- `allow_direct_close` 影响报警处理权限和闭环流程，正式实现前需要产品确认页面行为。

## 7. alarm_workorder 报警工单实例表

表定位：保存报警触发后生成的工单实例。本期按一条报警最多一个工单实例设计。

| 字段 | 类型建议 | 默认值 | 是否必填 | 字段功能 |
| --- | --- | --- | --- | --- |
| `workorder_id` | `bigint` | 雪花 ID 或自增 | 是 | 工单实例主键。 |
| `workorder_no` | `varchar(50)` | 无 | 是 | 工单编号。必须唯一，用于页面展示和外部引用。 |
| `alarm_id` | `bigint` | 无 | 是 | 关联报警 ID。必须唯一，防止一条报警重复生成工单。 |
| `alarm_configure_id` | `bigint` | `NULL` | 否 | 来源报警配置 ID 快照。 |
| `workorder_config_id` | `bigint` | `NULL` | 否 | 来源工单配置 ID 快照。 |
| `workorder_type` | `varchar(50)` | `NULL` | 否 | 工单类型快照。 |
| `workorder_priority` | `char(2)` | `NULL` | 否 | 工单优先级快照。 |
| `title` | `varchar(200)` | `NULL` | 否 | 工单标题。由模板或报警标题生成。 |
| `content` | `varchar(1000)` | `NULL` | 否 | 工单内容。由模板或报警内容生成。 |
| `device_sn` | `varchar(100)` | `NULL` | 否 | 报警设备 SN 快照。 |
| `device_type` | `varchar(30)` | `NULL` | 否 | 报警设备类型快照。 |
| `alarm_type` | `char(2)` | `NULL` | 否 | 报警类型快照。 |
| `alarm_rank` | `char(2)` | `NULL` | 否 | 报警等级快照。 |
| `alarm_time` | `datetime` | `NULL` | 否 | 报警发生时间快照。 |
| `assignee_type` | `varchar(30)` | `NULL` | 否 | 派单类型快照。 |
| `assignee_id` | `bigint` | `NULL` | 否 | 当前处理人或派单对象 ID。 |
| `assignee_name` | `varchar(100)` | `NULL` | 否 | 当前处理人或派单对象名称快照。 |
| `status` | `char(2)` | `'0'` | 否 | 工单状态。建议 `0` 待接单，`1` 处理中，`2` 已处理，`3` 已关闭，`4` 退回，`5` 取消。 |
| `timeout_time` | `datetime` | `NULL` | 否 | 工单超时时间。由报警时间和 `timeout_minutes` 计算。 |
| `finish_time` | `datetime` | `NULL` | 否 | 工单完成时间。 |
| `close_time` | `datetime` | `NULL` | 否 | 工单关闭时间。 |
| `handle_result` | `varchar(500)` | `NULL` | 否 | 工单处理结果摘要。 |
| `handle_remark` | `varchar(1000)` | `NULL` | 否 | 工单处理说明。 |
| `attachments_json` | `json` | `NULL` | 否 | 工单处理附件 JSON。 |
| `tenant_id` | `bigint` | `NULL` | 否 | 租户 ID。 |
| `del_flag` | `char(2)` | `'0'` | 否 | 逻辑删除标识。 |

### 约束建议

- `PRIMARY KEY (workorder_id)`。
- `UNIQUE KEY uk_alarm_workorder_no (workorder_no)`。
- `UNIQUE KEY uk_alarm_workorder_alarm (alarm_id)`。
- `INDEX idx_alarm_workorder_config (workorder_config_id)`。
- `INDEX idx_alarm_workorder_status (tenant_id, status, create_time)`。
- `INDEX idx_alarm_workorder_assignee (assignee_id, status)`。

### 写入时机

- 报警产生并命中自动工单配置时创建。
- 工单接单、处理、关闭、退回、取消时更新状态和处理字段。
- 工单创建成功后回写 `alarm.workorder_id`。

### 读取用途

- 工单列表和详情。
- 报警详情展示关联工单。
- 工单处理同步报警处理流水。

### 注意事项

- 转派不新增第二条 `alarm_workorder`，只更新当前处理人并写处理流水。
- 唯一键冲突应作为幂等场景处理，不能直接导致 MQ 无限重试。

## 8. active_push_config 主动推送配置表

表定位：保存推送配置。继续与 `pushConfigId_deviceSn` 共同完成设备级推送绑定。

| 字段 | 类型建议 | 默认值 | 是否必填 | 字段功能 |
| --- | --- | --- | --- | --- |
| `message_type` | `varchar(30)` | `NULL` | 否 | 推送消息类型，对应 `alarm_configure.push_message_type`。本次业务上作为推送细分匹配字段。 |
| `push_channel_type` | `varchar(20)` | `NULL` | 否 | 推送渠道类型，如 `WEBSOCKET`、`SMS`、`EMAIL`、`MQTT`、`WECHAT`、`HTTP`。 |
| `bind_ip` | `varchar(64)` | `NULL` | 否 | 可选字段。仅当 `push_address` 无法表达绑定 IP 时新增，用于记录推送配置绑定的 IP 或网段。 |

### 写入时机

- 新增或修改推送配置时写入。
- 修改后刷新 Redis 路由。

### 读取用途

- 推送服务根据 `message_type` 和设备/行业路由查找配置。
- 推送消费者根据 `push_channel_type` 决定使用 WebSocket、HTTP、MQTT 等渠道。

### 注意事项

- `message_type` 字段不要和 RabbitMQ 队列名强绑定。
- 旧配置如果只使用系统级 `messageType`，仍需兼容。
- `bind_ip` 是可选字段，不应作为本期主链路必需字段。

## 9. pushConfigId_deviceSn 推送配置设备绑定表

表定位：继续保存推送配置与设备 SN 的绑定关系。

| 字段 | 类型建议 | 默认值 | 是否必填 | 字段功能 |
| --- | --- | --- | --- | --- |
| `device_sn` | `varchar(100)` | 无 | 是 | 设备 SN。用于设备级推送配置路由。 |
| `active_push_config_id` | `bigint` | 无 | 是 | 推送配置 ID。关联 `active_push_config.active_push_config_id`。 |

### 写入时机

- 新增推送配置并绑定设备时写入。
- 修改推送配置设备范围时先删除旧绑定，再写入新绑定。
- 删除推送配置时删除对应绑定。

### 读取用途

- 推送配置详情回显绑定设备。
- 推送服务刷新 Redis 设备级路由。

### 注意事项

- 本期不强制为该表新增行业字段。
- 行业级和行业全部报警推送优先通过 Redis 路由语义实现。
- 如果后续需要 DB 层直接表达行业级推送配置，应单独评审是否新增推送范围表，避免污染当前设备绑定表。

## 10. 字段落库通用要求

- 新增字段优先 nullable 或提供默认值，降低旧数据兼容风险。
- 涉及分片表的字段必须同步基础表、物理分片表、建表逻辑和迁移脚本。
- JSON 字段在不支持原生 JSON 的数据库版本中可使用文本字段兼容，但字段语义不变。
- 所有影响报警行为的配置变更必须能通过 `config_version` 和快照追溯。
- 所有新增字段上线前必须先在测试库执行 DDL 验证，再联调代码写入。
