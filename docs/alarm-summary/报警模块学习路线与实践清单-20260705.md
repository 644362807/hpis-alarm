# 报警模块学习路线与实践清单

## 1. 学习目标

本文用于帮助新人或接手者系统学习 `hpis-alarm`。学习完成后，应能独立回答：

- 报警 start 和 stop 链路如何保证高吞吐和最终一致。
- 时间 + 容量分片如何路由、建表和刷新。
- cid hot/stale route 的生命周期是什么。
- MQ batch、stop event、side effect、snapshot worker 的边界是什么。
- 工单/推送当前最终口径是什么，哪些旧文档不能作为实现依据。
- 如何判断一次 alarm 修改是否风险可控。

## 2. 学习前置规则

学习前必须先接受以下规则：

- 先读当前权威，再读历史文档。
- 过时文档只用于理解演进，不用于实现。
- 测试报告中的性能数字必须看采样条件和不采纳条件。
- 任何批量 SQL、worker、MQ ack/nack、push payload 改动都属于高风险改动。

## 4. 第二阶段：理解分片和 ID

### 必读文档

1. `doc/报警时间容量分片设计说明.md`
2. `doc/报警分片数据链路说明.md`

### 学习重点

- 旧 `alarm_id % 5` 为什么被替换。

- actualDataNodes 为什么需要预注册和 DataSource 刷新。
- 当前月 `00..255`、下个月 `00..09`、月末只创建下月 `00` 的关系。

### 自测问题

- 如果新建了物理表，ShardingSphere 4.1.1 会自动发现吗。
- 为什么动态建表后主动刷新只是补充机制。
- 多实例部署时 `worker-id` 为什么必须不同。
- 长期历史为什么不能依赖 cid route 查询。

### 实践任务

- 根据一个假设时间 `2026-07-05 10:00:00` 说明可能路由到哪个 monthKey 和 tableSuffix。
- 说明一次服务启动时会创建哪些表、注册哪些 actualDataNodes。
- 写出按内部 `alarm_id` 查询和按时间范围查询的路由差异。

## 5. 第三阶段：理解 MQ start 和 batch

### 必读文档

1. `doc/报警压测与Profiling测试报告.md`
2. `doc/本轮修改记录-20260523-清理自研聚合保留consumer-batch.md`
3. `doc/报警分片数据链路说明.md`

### 学习重点

- 旧单条 listener、自研聚合、Spring AMQP consumer batch 的差异。
- 为什么自研 `submitAndWait` 聚合被清理。
- batch listener 为什么先处理同批 start，再处理 stop/status。
- 批量失败后为什么要复用 prepared context。
- ack/nack 为什么仍逐条执行。

### 自测问题

- batchSize 配成 200，不等于实际每批一定 200，为什么。
- 设备缓存缺失的 start 为什么是当前 item DROP，而不是整批失败。
- 批量事务成功但 ack 前宕机，系统依靠什么兜底。

### 实践任务

- 根据 `insertConsumerBatchEnabled=true` 的推荐配置，解释每个参数影响。
- 画出 batch listener 的消息处理顺序。
- 说明 batch 模式下哪些行为必须保持与旧 push payload 兼容。

## 6. 第四阶段：理解 stop 可靠化

### 必读文档

1. `doc/报警停止可靠化与批量关闭设计说明.md`
2. `doc/报警SQL循环与批处理风险治理计划-20260530.md`
3. `doc/本轮修改记录-20260531-stop-worker-PROCESSING认领.md`
4. `doc/本轮修改记录-20260602-stop可靠性审核修复.md`

### 学习重点

- stop event 是可靠缓冲表，不是历史表。
- `PENDING -> PROCESSING -> APPLIED/PENDING/FAILED` 状态机。
- `lock_token`、`event_version`、`available_time` 的作用。
- route missing 为什么先重试而不是立即失败。
- side effect 为什么不阻塞核心消警。
- outbox 创建失败为什么必须回滚核心关闭。

### 自测问题

- MQ stop 为什么落库成功后就 ack。
- worker 崩溃后 PROCESSING 如何恢复。
- 重复 stop 如何保持最新 stop_time。
- 为什么不能在异常时无界逐条 fallback。

### 实践任务

- 写出 stop event 一条记录从收到 MQ 到 APPLIED 的完整状态变化。
- 说明 route 查不到、route 已 CLOSED、route 后到三种情况的处理。
- 对照 SQL 批处理文档，标出哪些 SQL 必须按 suffix 分组。

## 9. 第七阶段：上手修改前检查

任何改动前，至少完成以下检查：

- 本次改动是否影响 MQ ack/nack。
- 是否改变 push payload 主结构。
- 是否新增或修改分片键。
- 是否新增批量 SQL，是否有 `500` 硬上限。
- 是否新增 worker，是否有 token、超时回收和 backlog 指标。
- 是否修改工单/推送，是否遵守 16 号权威文档。
- 是否需要同步运行配置说明、链路说明、压测报告或 README 权威索引。

## 10. 学习验收

完成学习后，应能用 30 分钟完成一次口头讲解：

1. 用 5 分钟讲 alarm 当前总体架构。
2. 用 5 分钟讲分片和内部 ID。
3. 用 5 分钟讲 MQ start batch。
4. 用 5 分钟讲 stop 可靠闭环。
5. 用 5 分钟讲电解槽异步投影和性能门禁。
6. 用 5 分钟讲工单/推送当前权威口径和过时文档隔离。

如果讲解中把过时工单方案当成当前实现依据，视为学习未通过。
